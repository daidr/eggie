# 终端查找

状态：现行实现，已完成实际交互验证，尚无延迟对照数据

`⌘F` 打开当前终端的查找框，支持普通文本、正则和前后匹配跳转。
关闭时回到终端输入；切换终端不把其他终端的查找结果带入当前终端。

## 响应与顺序

- 输入查询有 16ms 合并窗口，搜索和快照请求在后台执行，不阻塞 GUI
- 同一查找框串行提交查询和导航；连续输入替换待处理的旧查询，连续导航保留按键顺序
- 结果同时校验查找框身份和查询代数，关闭、重新打开或修改查询后不应用旧结果
- 快照只向新版本更新，高亮只显示在对应 revision 的快照上
- daemon 在未变更的缓冲中导航时复用匹配数量，终端发布新 revision 后重新统计

搜索仍使用终端内核的正则及跨行匹配语义，首次查询需要遍历回滚缓冲；缓存只保留
当前查询的统计与光标，不建立无界历史索引。

## 验证

真实 PTY 搜索测试覆盖文本、正则、前后导航和重叠匹配。
2026-10-17 在独立测试终端生成 3000 行内容，验证连续输入、重复 Enter、修改查询、
唯一匹配、无结果、关闭重开与切换标签；旧查询高亮未带入新终端。
持续刷新的输出和跨窗口交互尚未做独立压力测量。长日志性能应固定回滚量、
窗口大小与输入序列，对比 GUI 响应和 daemon 查询耗时，不能用编译成功代替性能结论。
