# 设计原则

这些原则来自用户在开发过程中的明确要求。具体行为和实现位置以关联设计为准。

## 交互优先

- 项目是组织终端的单位，窗口是展示位置；切换、移动和关闭窗口应保持终端身份与进程连续
- 控件的外观和行为一致：加号创建、箭头展开、点击终端聚焦；不让一个入口承担含糊的多重动作
- 信息留在使用它的上下文中。SSH 端口属于当前远端终端的信息面板，不挤占独立顶层标签页
- 复用现有控件和基础能力，包括选择器、连续圆角和原生弹窗，避免各页自行绘制不同版本
- hover 必须即时响应；可交互节点使用稳定 ID，不能依赖下一次无关 UI 刷新才显示状态
- 长文本默认截断并在溢出处加渐变；hover 后缓慢移动至末尾停止，不无限循环打扰阅读
- 预览有合理的首次悬停等待；已经出现的预览直接跟随目标切换，不消失后重开

## 动画表达变化

- 新增、删除、排序通过连续的位移与平面旋转表达身份变化，不能只替换图片再淡入淡出
- 单图标不倾斜；倾斜属于堆叠，堆叠左缘保持对齐
- 文字让位、行高变化、弹窗进出都使用自然的非线性过渡；中断和反向时从当前可见状态继续
- 自定义 Metal 内容与普通 UI 共享位移、裁剪和透明度语义，不能在退出动画时突然消失
- 尊重系统减少动态效果设置；关闭后的异步任务不能重新打开弹窗

## 视觉是一套系统

- 按钮、终端容器、标签、侧边栏行和主题卡使用同一连续 R 角能力；换曲线不能让名义圆角明显缩小
- 同层级的浮层共享边框、阴影与表面颜色，例如 SSH 连接状态和终端搜索
- 进程图标优先采用本地彩色 SVG；清洗资源并校准视觉大小，不能只比较 viewBox 数值
- 图标容器为圆角长方形，平面旋转不造成形变；边缘层次用细微阴影、柔和高光与克制的底部暗部
- OSC 7501 状态和终端进度使用角标，不替换主进程图标
- UI 配色与终端配色独立推导，保留主题色相与特制背景的风格，同时验证文字、hover、active 和按钮可读性
- 主题顺序稳定，分隔线前固定内置默认主题；选中态不重排列表，外侧选中环保留卡片原有细边框

## 文案尽量少

- 标题、选项或占位内容已经说明的事，不再加一句重复说明
- 状态直接表达结果，例如“进程已结束”；不在产品界面解释实现细节
- 仅在影响选择、存在边界或需要纠错时提供说明；短说明和控件标签不加句号
- 优先用熟悉、具体的动作词，避免“命令内容”一类缺少上下文的抽象名称

## 性能与结构

- 优化不能牺牲视觉效果、输入响应或交互流畅度；隐藏信息按需获取，不保留无界缓存
- 性能结论须固定负载、区分 GUI/daemon/子进程，并给出测量边界；历史峰值不是当前内存承诺
- 根据独立职责和所有权拆 crate；单个侧栏或设置页先拆模块，不按控件数量制造依赖层级
- 早期架构允许破坏性改动，优先清晰模型；涉及数据丢失和进程中断时仍需明确处理
- 简洁实现应能用一句具体注释解释核心取舍，避免时序补丁和多份事实来源
